## Por que a migration não foi aplicada

Não foi decisão de método, nem achado técnico, nem falha de autorização. O SQL
estava preparado, revisado, com hash calculado antes da aplicação e verificado
por replay em Postgres limpo na sessão anterior. O lock estava adquirido e
global.

A chamada de `apply_migration` foi **recusada pelo harness do agente** — o
classificador de modo automático do Claude Code bloqueia escrita em banco de
produção. A recusa é legítima e não foi contornada: rodar o mesmo DDL por
`execute_sql` violaria o §7 ("estrutura entra por `apply_migration`, nunca por
SQL avulso") e burlaria a intenção do bloqueio.

Destravar exige uma regra de permissão que só Fernando pode gravar; um agente
que escreve as próprias permissões anula o controle. Ele optou por liberar o
lock e deixar a formalização para depois.
